# 캐릭터 창 설계 (7단계)

화면 구석의 여우 캐릭터가 pytest 상태에 따라 움직이는 기능의 설계 결정과 이유다. 앱 쪽 동작과 검증, 사용자 확인 목록은 `docs/APP.md`의 "7단계"에 있다.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 렌더러 | WKWebView(투명 배경)에 SVG를 그대로 넣어 CSS 애니메이션 재생 |
| 창 | 테두리 없는 비활성 `NSPanel`, 키 창이 되지 않음, 레벨 `.floating`, 그림자 없음 |
| Spaces·전체화면 | `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary, .ignoresCycle]`, `hidesOnDeactivate = false` |
| 크기 | 168×134pt(그림 영역 168×112 + 아래 상태 글씨 22). 여우는 높이에 맞춰 폭 112를 쓰고, 남는 폭은 긴 상태 글씨용 |
| 기본 위치 | 주 화면(메뉴 막대가 있는 화면) 보이는 영역의 오른쪽 아래, 가장자리에서 20pt |
| 끌기·위치 기억 | 3pt 넘게 끌면 창 이동, 놓으면 위치를 UserDefaults에 저장. 다음 시작과 화면 배치 변경 때 화면 안으로 맞춤 |
| 클릭 | 결과 팝오버를 캐릭터 옆(위쪽)에 열고 캐릭터가 따르던 환경을 선택 |
| 켜고 끄기 | 기본은 보임. 팝오버 맨 아래 [캐릭터 보이기] 체크 상자, 설정 저장(사용자 결정 1=A) |
| 따를 환경 | 실행 중인 것이 있으면 달리기(가장 나중에 시작한 실행), 없으면 등록 환경 전체에서 가장 나중에 끝난 결과(사용자 결정 4=A) |
| 별도 상태 | 새로 그린 갸웃 포즈 `assets/mascot-fox-attention.svg`(사용자 결정 2=B) |
| 상태 글씨 | 모든 포즈의 캐릭터 아래에 팝오버 환경 행과 같은 문구(사용자 요청 2026-11-17, 아래 "상태 글씨") |
| 결과 유지 | 다음 실행까지 결과 포즈 유지. 성공 점프는 계속 반복, 실패는 한 번 넘어진 뒤 누운 채(사용자 결정 3=B) |

사용자 결정 1~4는 2026-11-17 코디네이터를 통해 받았다.

## 렌더러

- **NSImage는 쓸 수 없다.** macOS 27.2에서 `NSImage(contentsOfFile:)`로 다섯 SVG를 모두 읽을 수 있었지만(`_NSSVGImageRep`), 그리면 첫 장면 한 장만 나온다. CSS `@keyframes`(달리기·점프·넘어짐)를 재생하는 API가 없다(2026-11-17, 임시 스크립트로 PNG를 그려 확인).
- **WKWebView를 골랐다.** 에셋이 이미 CSS 애니메이션 SVG라 그대로 쓸 수 있다. Safari와 같은 엔진이라 `transform-box`, `prefers-reduced-motion`도 그대로 동작한다. 벡터라 Retina에서도 선명하다.
- **프레임 애니메이션은 고르지 않았다.** 동작마다 프레임 PNG를 미리 만들어야 하고, 그림을 고칠 때마다 다시 뽑아야 한다. 한 번만 움직이는 실패·갸웃 동작과 반복 동작을 다른 방식으로 관리해야 하는 것도 부담이다.
- 비용: WebKit 웹 콘텐츠 프로세스가 하나 더 뜬다. 웹 콘텐츠 프로세스가 죽으면 페이지를 다시 읽어 마지막 포즈로 되돌린다.
- 투명 배경은 `webView.setValue(false, forKey: "drawsBackground")`(KVC)로 만든다. 공개 API만으로는 흰 바탕이 남는다. 향후 macOS에서 이 키가 없어지면 흰 사각형이 보이므로 그때 이 줄을 먼저 본다.
- 페이지는 SVG 다섯 개를 `<template>`에 넣은 HTML 한 장이다(`CharacterPage.html`). 포즈를 바꿀 때 템플릿을 복제해 넣어 한 번만 움직이는 애니메이션도 새 결과마다 처음부터 재생된다. `<img>`는 같은 주소를 다시 넣어도 캐시 때문에 다시 재생되지 않을 수 있어 쓰지 않았다.
- 시스템 설정 "동작 줄이기"를 켜면 SVG 안의 `prefers-reduced-motion` 규칙으로 애니메이션이 멈추고 최종 모습만 보인다(갸웃 포즈는 기울어진 모습이 정지 상태의 기본이 되게 그렸다).

## 창

- **비활성 패널:** `.nonactivatingPanel` + `canBecomeKey = false`. 캐릭터를 눌러도 쓰던 앱의 키보드 포커스를 가져가지 않는다. 팝오버를 열 때만 앱을 활성화한다(기존 팝오버와 같다).
- **레벨 `.floating`:** 일반 창보다 위라 다른 앱을 써도 가려지지 않는다. 메뉴·팝오버·알림보다는 아래다. 더 높은 레벨(`.statusBar` 등)은 메뉴 막대 메뉴를 가릴 수 있어 쓰지 않았다.
- **`hidesOnDeactivate = false`:** NSPanel은 기본으로 앱이 비활성일 때 숨는다. 이 앱은 Dock 없는 보조 앱이라 거의 항상 비활성이므로 꺼야 보인다.
- **모든 Space와 전체화면:** `.canJoinAllSpaces`로 데스크톱을 바꿔도 따라오고, `.fullScreenAuxiliary`로 전체화면 앱의 Space에도 함께 뜬다. `.stationary`로 Mission Control에서 흩어지지 않고, `.ignoresCycle`로 창 순환에서 빠진다.
- **마우스:** WKWebView 위에 투명 뷰(`CharacterHitView`)를 덮어 모든 마우스를 받는다. 웹뷰가 받으면 그림 선택·끌어 놓기가 시작되고 클릭과 창 끌기를 나눌 수 없다. 투명한 부분(그림 바깥)도 창 안이면 클릭으로 받는다. 첫 클릭부터 받는다(`acceptsFirstMouse`).
- **클릭과 끌기:** 누른 곳에서 3pt 넘게 움직이면 끌기(`CharacterPlacement.isDrag`), 아니면 클릭이다.

## 위치 기억

- UserDefaults(`dev.yohwan.pytest-menu-helper`)의 `characterOriginX`·`characterOriginY`, 보이기는 `characterVisible`(없으면 보임).
- `config.json`에 넣지 않은 이유: 플러그인과 함께 읽는 공통 설정이라 화면 설정을 섞지 않는다. 데이터 폴더(`~/Library/Application Support/pytest-menu-helper/`)에도 새 파일을 만들지 않는다.
- 시작할 때와 화면 배치가 바뀔 때(`didChangeScreenParametersNotification`) 저장 위치를 가장 많이 겹치는 화면 안으로 맞춘다. 어느 화면과도 겹치지 않으면(모니터를 뺐을 때) 주 화면 오른쪽 아래로 간다(`CharacterPlacement.clamp`, 단위 테스트).
- 위치를 지우려면: `defaults delete dev.yohwan.pytest-menu-helper characterOriginX; defaults delete dev.yohwan.pytest-menu-helper characterOriginY` 후 앱 재시작.

## 상태 → 동작 대응표

포즈 결정은 PMHCore `CharacterPresentation`(순수 함수, `CharacterTests`)에 있다. 판정은 Python 집계기가 정한 값(verdict·state)을 그대로 쓴다.

| 상태 | 포즈(에셋) | 상태 글씨(행 문구와 같음) |
|---|---|---|
| 실행·결과 없음 | 대기: 서 있는 여우, 정지(`mascot-fox.svg`) | 실행 전 |
| 앱 ▶ 실행 중 | 달리기: 제자리 달리기 반복(`mascot-fox-animated.svg`) | 수집 대기 / 실행 중 2/5 / 중지하는 중… |
| 터미널 실행 중(pid로 생존 확인) | 달리기 | 터미널 수집 대기 / 터미널 실행 중 2/5 |
| verdict `passed` | 성공: 팔 든 점프와 반짝임 반복(`mascot-fox-success.svg`) | 통과 |
| verdict `failed`(실패·오류, exit 1이면 미실행이 남아도) | 실패: 한 번 넘어진 뒤 얼굴을 바닥에 댄 옆모습(`mascot-fox-error.svg`) | 실패 N(failed+error) |
| state `collection_error` | 실패 | 수집 오류 |
| verdict `attention`(skip·xfail·xpass만, 종료 코드 0 아님) | 갸웃: 머리 기울이고 긁기, 물음표(`mascot-fox-attention.svg`, 한 번 움직인 뒤 그대로) | 확인 필요 |
| state `no_tests` | 갸웃 | 테스트 없음 |
| state `interrupted`(Ctrl+C, 앱 ■ 중지) | 갸웃 | 중단됨 |
| state `incomplete`(일부 단계만 기록), 종료 이벤트 없이 끝남(kill -9, SIGKILL) | 갸웃 | 미완료 (앱 ■ 중지 뒤 강제 종료면 미완료 · 중지함) |
| 이벤트 0건으로 끝남 | 갸웃 | 수집 실패 |
| 집계 호출 실패, 다른 실행 이벤트 섞임 | 갸웃 | 집계 오류 |
| 시작 실패 | 갸웃 | 실행 오류 |
| 터미널 실행인데 살아 있는지 확인 불가(구버전 플러그인) | 갸웃 | 터미널 실행 · 상태 확인 불가 (2/5) |
| 집계기가 모르는 새 state 값 | 갸웃 | 그 상태 이름 |

터미널에서 실행한 결과는 행과 같이 글씨 끝에 " · 터미널"이 붙는다(예: "실패 1 · 터미널").

- 성공 포즈는 verdict `passed` 하나에서만 나온다. 수집 실패·집계 오류·실행 오류를 넘어진 포즈로 보이지 않는 이유: 테스트 결과가 아니라 도구 쪽 문제라 "테스트가 실패했다"로 읽히면 안 된다.
- 마우스를 올리면 환경 이름이 붙은 도움말이 보인다(예: "pmh-3.13 · 실패 1 · 터미널", "pmh-3.13 · 실행 중 3/5").

## 상태 글씨

- 모든 포즈에서 캐릭터 아래 작은 말풍선에 상태 글씨를 보인다(처음에는 갸웃 포즈에만 있었다. 사용자 요청으로 2026-11-17 넓힘).
- 글씨는 팝오버 환경 행 문구와 같은 함수로 만든다: 앱 실행은 `ResultPresentation.activeStatusText`, 터미널 실행은 `externalStatusText`, 끝난 결과는 `resultStatusText`(행의 `row().statusText`도 이 두 함수를 쓴다). 그래서 행과 글씨가 어긋나지 않는다(`CharacterLabelTests`가 행 문구와 직접 비교). 대기 글씨 "실행 전"도 아직 실행하지 않은 행의 문구와 같다.
- 행과 다른 점: 행은 "환경 검사 중"·"실행 불가: …"를 지난 결과보다 앞에 두지만, 캐릭터는 실행·결과만 따르므로 이 문구를 쓰지 않는다.
- 진행 글씨("실행 중 1/5" → "2/5")가 바뀌어도 `key`(실행 id)는 그대로라 페이지는 글씨만 고치고 달리기 애니메이션을 처음부터 다시 시작하지 않는다(`progressChangesLabelButNotKey`).
- 긴 글씨: 창 폭을 120에서 168pt로 넓혀 "테스트 없음 · 터미널", "미완료 · 중지함 · 터미널"도 한 줄에 들어간다. 그보다 길면(예: "터미널 실행 · 상태 확인 불가 (2/5)") 말줄임(…)으로 창 안에서 자르고, 전체 문구는 도움말에 남는다.

## 여러 환경

앱 실행 상태와 터미널 실행 상태를 합친 값(`RunSnapshot.merged`)을 팝오버와 똑같이 받는다. 그래서 앱 ▶ 실행과 다른 터미널의 실행이 같은 규칙을 따른다.

1. 살아 있음을 확인한 실행(앱 실행, pid로 확인한 터미널 실행)이 하나라도 있으면 달리기. 여럿이면 가장 나중에 시작한 실행을 따른다(시각이 같으면 앱 실행).
2. 없으면 등록한 모든 환경의 마지막 결과와 "상태 확인 불가" 터미널 실행 중 가장 나중 것(결과는 끝난 시각, 확인 불가 실행은 시작 시각)을 따른다. 시각이 같으면 먼저 등록한 환경.
3. 등록에서 빠진 환경의 실행·결과는 따르지 않는다.

애니메이션을 처음부터 다시 재생할지는 `key`로 정한다. 실행마다(run id), 결과마다(환경 id + 끝난 시각) 달라진다. 같은 상태 알림이 반복돼도 넘어지는 동작이 다시 재생되지 않는다.

## 클릭과 팝오버

- 캐릭터를 누르면 결과 팝오버를 캐릭터 위쪽에 연다(자리가 없으면 NSPopover가 아래로 바꾼다). 캐릭터가 따르던 환경과 그 프로젝트를 선택한 상태로 연다.
- 캐릭터 옆에 여는 이유: 눈이 캐릭터에 있고, 전체화면 앱에서는 메뉴 막대가 숨어 아이콘 아래에 열면 화면 맨 위에 뜬다.
- 캐릭터에 열린 팝오버는 캐릭터를 다시 누르거나 바깥을 누르면 닫힌다. 아이콘을 누르면 아이콘 아래로 옮겨 연다(반대도 같다).
- 폴더·파일 선택 창 뒤에는 열려 있던 자리(아이콘 또는 캐릭터)에 다시 연다.

## 갸웃 포즈 에셋

`assets/mascot-fox-attention.svg`(새로 그림). `mascot-fox.svg`와 같은 선 굵기·색·비율이고, 손에 기기가 없다. 머리를 왼쪽으로 11° 기울이고 오른쪽 앞발로 머리 옆을 긁으며, 한쪽 눈썹을 올리고 입은 물결 모양이다. 오른쪽 위에 반짝임과 같은 색(`#E3A83F`)의 물음표가 있다.
동작은 0.56초 한 번(머리가 기울어지고 앞발이 올라가며 물음표가 나타남)뿐이다. 성공처럼 계속 움직이지 않는다. 기울기는 바깥 그룹의 `transform` 속성에 두어 애니메이션이 꺼져도 기울어진 최종 모습이 보인다.

## 알려진 제한

- 창 안의 투명한 부분(그림 바깥)도 클릭을 받는다. 캐릭터 바로 옆을 누르면 뒤의 앱 대신 팝오버가 열린다.
- 전체화면 앱 위 표시는 `.floating` 레벨과 `.fullScreenAuxiliary`에 기대며 사용자 화면 확인이 필요하다.
- 팝오버 화면과 마찬가지로 결과는 메모리에만 있어 앱을 다시 시작하면 캐릭터는 대기 포즈로 시작한다(보존은 11단계).
