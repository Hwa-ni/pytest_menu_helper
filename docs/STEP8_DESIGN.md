# 8단계 설계: 완료 알림과 기본 기능 데모 정리

상태: **구현과 자동·통합 검증 완료, 화면 일부 확인(2026-11-17).** 알림 표시·클릭과 중단 때 알림 없음은 사용자가 확인했고, 알림 거부 안내·토글·폴더 다시 지정·데모 대본은 확인 대기다. 아래 "정할 것" 5가지는 모두 추천안으로 구현했다. 검증 기록은 `docs/APP.md` "8단계" 절, 화면 확인 목록은 같은 절의 "8단계 사용자 확인"이다.

범위 원본은 `IMPLEMENTATION_PLAN.md`의 "8. 완료 알림과 기본 기능 데모 정리하기"다.

- 알림 권한을 요청하고, 허용된 경우 실행 완료 알림을 보낸다.
- 알림에 결과 요약을 담고 같은 실행의 알림은 한 번만 보낸다.
- 권한이 거부돼도 팝오버와 캐릭터로 결과를 확인할 수 있게 한다.
- 앱 재실행, 프로젝트 경로 변경, 플러그인 누락 때의 동작을 점검한다.
- 설치·실행·데모 절차와 지원 범위를 README에 적는다.

완료 기준: 성공·실패·중단이 들어간 데모를 다시 만들 수 있고, 알림을 허용한 상태와 거부한 상태 모두에서 앱이 정상 동작한다.

## 1. 지금 알고 있는 것

2.5단계 알림 샘플(`docs/NOTIFICATION_BUNDLE.md`, `spikes/notification-sample/`)에서 확인한 사실이다.

- 알림이 뜨려면 세 가지가 모두 필요하다. Bundle ID가 있는 .app, 서명(ad-hoc 이상), `open`으로 실행. 실제 앱(`dev.yohwan.pytest-menu-helper`)은 `app/build.sh`가 이 조건으로 만든다.
- 첫 실행에서 권한 팝업이 보이지 않고 곧바로 `denied`가 나왔다. 사용자가 시스템 설정 > 알림에서 직접 허용한 뒤에야 알림이 떴다. 원인은 모른다. 그래서 앱 안에 권한 안내가 필요하다.
- ad-hoc 서명은 빌드할 때마다 서명 정보가 바뀐다. 다시 빌드하면 macOS가 다른 앱으로 보고 알림 권한을 잃을 수 있다. 아직 시험하지 않았다(아래 "위험").
- 지금 앱은 `UserNotifications`를 쓰지 않는다. 결과는 메모리에만 있어 앱을 다시 켜면 사라진다(보존은 11단계).

코드에서 확인한 것도 있다.

- 프로젝트 폴더가 없어져도 환경 검사는 이를 잡지 않는다. ▶를 눌러야 "프로젝트 폴더가 없습니다" 오류가 난다(`RunController.swift`).
- 데모에 쓰는 느린 샘플은 저장소 밖(`~/.pmh-build/slow-sample`)에 있다. 다른 사람이 데모를 그대로 따라 할 수 없다.
- README의 "현재 구현 상태"는 1~4단계, Swift 134개 기준이라 낡았다.

## 2. 알림

### 2.1 무엇을 언제 보내나

실행 하나가 끝나 결과가 정해지면 알림 1건을 보낸다. 결과는 앱 ▶ 실행이든 터미널 실행이든 팝오버와 캐릭터가 쓰는 같은 상태(`RunSnapshot.merged`)에서 가져온다.

| 결과 | 보내나(추천안) | 이유 |
|---|---|---|
| 통과 | 보냄 | 기다리던 결과 |
| 실패·오류·수집 오류 | 보냄 | 가장 알아야 할 결과 |
| 확인 필요(skip·xfail·xpass만) | 보냄 | 통과로 착각하지 않게 |
| 테스트 없음 | 보냄 | `-k` 오타 등을 바로 알게 |
| 미완료(kill -9, 터미널 닫힘) | 보냄 | 예상하지 못한 끝남 |
| 중단됨(■ 중지, Ctrl+C) | **보내지 않음** | 사용자가 직접 멈춘 것이라 이미 안다 |

### 2.2 알림 내용

제목과 본문은 팝오버 행 문구와 같은 함수에서 만든다. 화면마다 문구가 달라지지 않게 하기 위해서다.

- 제목: `통과 · slow-sample / pmh-3.13` 또는 `실패 1 · fastapi_demo / pmh-3.13`. 터미널 실행이면 끝에 ` · 터미널`.
- 본문: 건수와 시간. 예: `통과 5 · 실패 0 · 9.9초`.
- 실패가 있으면 본문 둘째 줄에 첫 실패 테스트 이름. 예: `test_main.py::test_fail 외 2건`.

### 2.3 한 번만 보내기

- 보낸 실행 ID를 메모리 집합에 넣고, 같은 ID는 다시 보내지 않는다. 결과가 여러 번 갱신돼도(앱 실행 결과와 터미널 결과가 합쳐질 때 등) 1건이다.
- 알림 요청의 identifier를 실행 ID로 준다. 같은 ID가 다시 들어가도 알림 센터가 덮어쓴다(이중 안전장치).
- 앱을 다시 켜도 중복이 생기지 않는다. 6단계 감시기가 앱을 켜기 전에 끝난 실행을 이미 무시하기 때문이다.

### 2.4 알림을 누르면

팝오버를 열고 그 실행의 환경을 고른다. 캐릭터 클릭과 같은 동작이다.

### 2.5 권한

- 앱을 켤 때 상태를 읽고(`getNotificationSettings`), 아직 정하지 않은 상태(`notDetermined`)일 때만 한 번 요청한다(`requestAuthorization`).
- 팝오버 맨 아래, [캐릭터 보이기] 옆에 [완료 알림] 토글을 둔다. 끄면 권한과 상관없이 보내지 않는다(설정 저장).
- 토글은 켰는데 권한이 거부됐으면, 팝오버 아래에 회색 한 줄을 보인다. "알림이 꺼져 있습니다. 시스템 설정 > 알림 > PytestMenuHelper에서 허용하세요." 옆에 [설정 열기] 버튼을 두고, 누르면 시스템 설정의 알림 화면을 연다.
- 권한이 없어도 다른 동작은 그대로다. 팝오버, 캐릭터, 실행·중지 모두 알림과 상관없이 돈다.

### 2.6 코드 구조

- `PMHCore/NotificationPresentation.swift`(새 파일, 순수 함수): 결과로 보낼지 정하고, 제목·본문·identifier를 만든다. 단위 테스트로 고정한다.
- `PMHApp/Notifier.swift`(새 파일): `UNUserNotificationCenter` 감싸기. 권한 읽기·요청, 보내기, 알림 클릭 처리(delegate). 보낸 실행 ID 집합.
- `AppDelegate`: 지금의 `pushPopoverState` 흐름에서 새로 끝난 결과를 Notifier에 넘긴다. 메인 스레드 전달 규칙(CFRunLoopPerformBlock common modes + CFRunLoopWakeUp)은 그대로다.
- 팝오버가 열려 있을 때도 알림은 보낸다(추천안). 앱이 앞에 있을 때도 배너가 보이게 delegate에서 `.banner`를 돌려준다.

## 5. 검증 계획

- 단위 테스트: 결과별 보낼지 여부, 제목·본문 문구(팝오버 행 문구와 직접 비교), 같은 실행 ID는 1번만, 중단은 보내지 않음, 토글 꺼짐이면 보내지 않음, 폴더 없음 검사.
- 통합(자동): 별도 셸에서 성공·실패·중단·kill -9를 돌리고, 앱 로그에 "알림 보냄 run=… 제목=…"과 "보내지 않음(중단)"이 남는지 본다.
- 사용자 화면 확인:
  1. 알림 허용 상태: 성공·실패·미완료 알림이 1번씩 뜨고 문구가 맞는가. 누르면 팝오버가 그 환경으로 열리는가.
  2. 중단은 알림이 없는가.
  3. 시스템 설정에서 알림을 끈 상태: 앱이 정상 동작하고 팝오버에 안내 줄과 [설정 열기]가 보이는가.
  4. [완료 알림] 토글을 끄면 알림이 없고, 앱을 다시 켜도 꺼진 채인가.
  5. 프로젝트 폴더 이름을 바꾸면 검사가 "폴더가 없습니다"를 보이고, [폴더 다시 지정]으로 고쳐지는가.
  6. 다시 빌드한 뒤에도 알림 권한이 유지되는가(아래 "위험").
  7. README 대본대로 데모가 처음부터 끝까지 되는가.

## 6. 위험

- **다시 빌드하면 알림 권한이 풀릴 수 있다.** ad-hoc 서명은 바이너리가 바뀔 때마다 바뀐다. 풀리면 개발 중에는 매번 시스템 설정에서 다시 허용해야 한다. 먼저 시험하고, 풀리면 README에 적는다. 근본 해결(고정 인증서로 서명)은 범위 밖이다.
  - **시험 결과(2026-11-17): 풀리지 않았다.** 앱 로그 `알림 권한 시작 상태=… cdhash=…`로 기록했다. 첫 빌드(cdhash ce1d06c3) 첫 실행은 `notDetermined`라 요청했지만 콜백 없이 대기했고, 재시작 뒤 `denied`였다. 사용자가 시스템 설정에서 허용한 뒤 코드를 바꿔 다시 빌드(2093c507)해도 `authorized`, 되돌려 다시 빌드(ce1d06c3)해도 `authorized`였다. macOS가 이 경우 권한을 Bundle ID 기준으로 기억한다. README "현재 구현 상태"에 적었다.
  - 주의: 소스가 같으면 다시 빌드해도 바이너리와 cdhash가 같다. 시험은 코드를 실제로 바꿔 cdhash가 달라진 빌드로 했다.
- **권한 팝업이 안 뜰 수 있다**(2.5단계에서 관찰). 그래서 안내 줄과 [설정 열기]를 둔다. 8단계에서도 첫 요청은 응답 기록 없이 `denied`로 끝났다(팝업이 떴는지는 확인하지 못함).
- 집중 모드(방해 금지)에서는 알림이 화면에 안 뜬다. 앱 문제가 아니므로 README에 한 줄 적는다.

## 7. 정할 것 (2026-11-17 결정: 모두 추천안)

1. **터미널 실행도 알림을 보낼까.** 추천: 보냄. 터미널을 띄워 두고 다른 일을 하다가 끝난 걸 알기 좋다. 대안: 앱 ▶ 실행만.
2. **중단됨도 알림을 보낼까.** 추천: 보내지 않음(직접 멈췄으니까). 대안: 보냄.
3. **팝오버가 열려 있을 때도 보낼까.** 추천: 보냄(단순하고 놓치지 않음). 대안: 팝오버가 열려 있으면 생략.
4. **프로젝트 폴더가 사라졌을 때.** 추천: 오류 표시 + [폴더 다시 지정](환경 유지). 대안: 오류 표시만 하고 제거 후 다시 등록.
5. **느린 샘플을 저장소 안 `examples/slow_demo/`로 옮길까.** 추천: 옮김.

## 8. 구현하며 정한 작은 해석 (2026-11-17)

설계에 없는 화면 갈림길은 나오지 않았다. 아래는 설계 문장을 코드로 옮기며 정한 해석이다.

- ■ 중지를 눌렀지만 제시간에 멈추지 않아 앱이 강제로 끝낸 "미완료 · 중지함"도 결정 2(직접 멈춘 실행)에 넣어 보내지 않는다. 외부 `kill -9`나 터미널 닫힘 미완료는 보낸다.
- 토글이 꺼진 동안 끝난 실행도 처리한 것으로 남긴다. 나중에 켰을 때 지난 결과 알림이 한꺼번에 오지 않게 하기 위함이다.
- 안내 줄의 앱 이름은 시스템 설정 알림 목록에 보이는 표시 이름(`CFBundleDisplayName`, "pytest Menu Helper")으로 썼다. 설계 초안의 "PytestMenuHelper"는 번들 이름이다.
- 폴더가 없어도 ▶는 끄지 않았다(설계 3절은 표시만 요구). 누르면 지금처럼 "실행 오류 · 프로젝트 폴더가 없습니다"가 된다.
- 알림 클릭 때 팝오버는 캐릭터가 보이면 캐릭터 옆, 숨겼으면 메뉴 막대 아이콘 아래에 연다.
- `examples/slow_demo/test_slow.py`는 테스트 내용을 그대로 옮기고, "저장소 밖"이라고 적힌 모듈 설명 한 줄만 고쳤다.
